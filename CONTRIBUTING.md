# Contributing

## Setup

Requires Python 3.11+ and [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/etka/blast-radius && cd blast-radius
make setup          # uv sync --all-extras --group dev, then pre-commit install
make test           # should be green immediately
cp .env.example .env
```

`make setup` installs every extra. If you only need the core pipeline:

```bash
uv sync --group dev
```

## Claude Code settings profile

Copy the profile for your role. This keeps your agent inside your half of the
project, which is what stops two agents editing the same file on day five.

```bash
cp .claude/settings.core.json .claude/settings.local.json   # OWNER A (@etka)
cp .claude/settings.ci.json   .claude/settings.local.json   # OWNER B (@teammate)
```

`.claude/settings.local.json` is gitignored, so you each get your own without
the two profiles fighting over one tracked file. Start Claude Code from the
repository root — the path rules anchor at the directory the session started in.

See [.claude/README.md](.claude/README.md) for what the rules do and, more
usefully, what they do not.

## Ownership

| Path | Owner |
| --- | --- |
| `core/`, `skill/` | **A — @etka** |
| `ci/`, `env/`, `.github/workflows/` | **B — @teammate** |
| `contracts/`, root docs, `examples/` | **both** |

`.github/CODEOWNERS` enforces this on pull requests. The rules in prose are in
[CLAUDE.md](CLAUDE.md); the interface between the two halves is in
[CONTRACT.md](CONTRACT.md).

**Do not edit outside your scope.** If a task seems to require it, stop and say
so — the answer is usually a change to `contracts/`, agreed by both owners.

## Branches

```
work/etka/<topic>          OWNER A
work/teammate/<topic>      OWNER B
```

- Pull requests into `main`. **No direct pushes to `main`.**
- One topic per branch. `work/etka/severity-engine`, not `work/etka/stuff`.
- A branch touching `contracts/` is named `work/<handle>/contract-<what>` so the
  other owner can see from the branch list that they are about to be needed.
- Rebase on `main` before opening the PR; merge commits from `main` into a topic
  branch make the two-owner history unreadable.

Branch protection to configure on the GitHub repository:

- require a pull request before merging
- require review from Code Owners
- require the `check` status to pass
- no force pushes to `main`

The one exception to "no force push" is `fix/blast-radius-<pr>` branches, which
are generated by the tool and owned entirely by it.

## Running things

```bash
make test        # pytest
make lint        # ruff check + ruff format --check
make fmt         # ruff format + ruff check --fix
make typecheck   # mypy strict
make check       # all of the above; this is what CI runs
make demo        # run the pipeline against a fixture, then list remaining stubs
make stubs       # what is left, grouped by owner
make doctor      # verify the DataHub read and write paths
```

Run a single owner's tests:

```bash
uv run pytest core/tests        # OWNER A
uv run pytest ci/tests          # OWNER B
uv run pytest contracts/tests   # the shared interface; both should watch this
```

### Where tests live

Tests sit next to the code they cover — `core/tests/`, `ci/tests/`,
`contracts/tests/` — rather than in one top-level `tests/`. That is deliberate:
it makes CODEOWNERS ownership of a test automatic, and it means the two owners
never touch the same test directory.

## Writing code here

The project's non-negotiables, each of which has a test:

1. **Python 3.11+, uv, ruff, mypy strict.**
2. **Deterministic core, model as judgment.** Severity, lineage traversal and
   diff parsing are pure deterministic code. The LLM writes prose and candidate
   fix code. `core/severity/` must not import `core/agent/`.
3. **No mock implementations.** A stub raises `StubNotImplementedError` with a
   docstring describing the intended contract. Never return plausible fake data.
4. **Every module boundary crossing goes through a typed model** validated
   against a schema in `contracts/`.
5. **Free text is untrusted**, preserved verbatim, and can never reach a
   severity score.

Everything — code, comments, docs, commit messages — is written in English.

### Implementing a stub

```bash
uv run blast-radius stubs --owner A      # find one
```

Then: read the docstring, which is the contract. Write the test first where
there is not already one — for OWNER B there usually is, as a strict xfail in
`ci/tests/`. Implement. When a strict-xfail test starts passing, pytest reports
the XPASS as a failure; delete the marker, that is the handshake.

Do not delete a stub's docstring when you implement it. The contract it
describes is still the contract.

## Pull requests

- Green `make check`.
- The PR body says what changed and, if it touches `contracts/`, why the
  interface had to move.
- A PR that touches both owners' directories should almost always be two PRs.
  The exception is a contract change, which must update both sides at once.
